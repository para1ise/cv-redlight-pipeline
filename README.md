# CV-пайплайн: проезд на красный свет

Тестовое задание «Computer Vision & Video Analytics», сценарий 3 (городской трафик).
Пайплайн читает видеофайл или live-поток, детектирует и трекает транспорт,
определяет сигнал светофора и фиксирует проезд контрольной линии на красный.

**Источник:** live-трансляция перекрёстка в Иокогаме, <https://www.youtube.com/watch?v=1CI685iPIUQ>
(1280×720, 30 FPS). Запись сделана 1 октября около 13:15 мск; в Иокогаме в это время
вечер (19:15), поэтому сцена ночная.

## Результат

| Файл | Что это |
|---|---|
| `outputs/demo/annotated.mp4` | Аннотированный фрагмент, 42 с |
| `outputs/demo/incidents.json` | Перечень инцидентов |

На фрагменте красный сигнал включается на 18-й секунде. На отметке 18.8 с стоп-линию
пересекает автомобиль — нарушение зафиксировано. Следом на красный проезжает мопед, но это
нарушение не поймано: трекер подхватывает мопед уже за линией, и пересечение не регистрируется.
Если перенести линию к середине перекрёстка, фиксируются оба нарушения.

Содержимое `incidents.json`:

```json
[
  {
    "timecode": "00:00:18.800",
    "event_type": "red_light_violation",
    "track_id": 42
  }
]
```

## Запуск

```bash
uv sync        # зависимости из pyproject.toml / uv.lock, PyTorch с CUDA 12.4

uv run python main.py --source data/demo_input.mp4 --output-dir outputs/demo            # файл
uv run python main.py --source https://www.youtube.com/watch?v=1CI685iPIUQ --max-seconds 45   # live-поток
uv run pytest tests                                                                     # тесты
```

`--source` принимает файл, RTSP/HLS-адрес или ссылку на YouTube-трансляцию.
Сцена (модель, линия, светофор, правило) задаётся в `--config`, по умолчанию `configs/yokohama.yaml`.
Веса `yolo11s.pt` (предобученные на COCO) скачиваются при первом запуске.
По умолчанию используется GPU; для запуска без видеокарты NVIDIA замените в конфиге
`device: 0` на `device: cpu`.

Инструменты: `utils/record_stream.py` — запись фрагмента эфира,
`utils/roi_picker.py` — разметка контрольной линии мышью.

## Архитектура

| Модуль | Ответственность |
|---|---|
| `src/tracking.py` | YOLO11s + ByteTrack. Единственный модуль, который знает про Ultralytics; наружу отдаёт список `Track` |
| `src/zones.py` | Геометрия контрольной линии: пересечение отрезков и сторона пересечения |
| `src/traffic_light.py` | Сигнал светофора по цвету в заданном прямоугольнике |
| `src/events.py` | Событийная логика: правило поверх треков, линии и сигнала. Не зависит от модели и видео |
| `src/render.py`, `src/export.py` | Оверлей и запись `incidents.json` / видео H.264 |
| `src/source.py` | Открытие файла, потока или YouTube-ссылки |

## Условия срабатывания ROI-алерта

Событие `red_light_violation` фиксируется, когда выполнены все условия:

1. **Сигнал красный.** В прямоугольнике `traffic_lights.roi` считаются яркие насыщенные
   пиксели красного, жёлтого и зелёного (HSV); побеждает цвет, набравший не меньше
   `min_pixels`. Смена состояния подтверждается тремя кадрами подряд.
2. **Линия пересечена.** Точка опоры трека (середина нижней грани рамки) перешла через
   `stop_line` между соседними кадрами. Пересечение отрезков проверяется по знакам
   векторных произведений.
3. **Направление — от камеры** (`direction: to_right`). Встречный поток не учитывается.
4. **Допуск истёк.** С момента включения красного прошло не меньше `grace_sec` (0.3 с).

Повторное срабатывание для того же трека блокируется на 1 с.

## Производительность

GTX 1650 (4 ГБ), YOLO11s, вход 960 px, FP32:

| Режим | FPS обработки |
|---|---|
| Файл 1280×720 (детекция + трекинг + события + оверлей) | 33.0 |
| Live-поток с YouTube | 26.8 |

FP16 выключен: на GTX 16xx он даёт NaN в координатах рамок.
Замер live-режима сделан до упрощения логики событий и не повторялся.

## Ограничения

- **Ночная сцена.** Уверенность детектора низкая (0.2–0.6), тёмные машины и мопеды
  на отдельных кадрах пропадают, номера треков растут быстро. Чтобы это исправить, нужно
  подбирать параметры трекера и проверить другие детекторы на ночных кадрах.
- **Пропуск мопеда.** На демо-фрагменте пойман один нарушитель из двух: мопед детектируется
  слишком поздно, уже за линией.
- **Линия контроля задаётся вручную.** Координаты `stop_line` выставлены в конфиге по разметке
  стоп-линии; автоматического поиска разметки нет.
- **Светофор проверен только ночью.** Способ опирается на яркость лампы и днём должен
  работать, но на дневной записи не проверялся. При масштабировании логику, возможно,
  придётся менять.
- **Одно направление.** Нарушением считается пересечение линии только при движении от камеры.
  Встречный транспорт пересекает эту же линию, уже покидая перекрёсток, и для него это не нарушение.
